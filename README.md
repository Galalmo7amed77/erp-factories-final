# نظام إدارة العمال والرواتب

واجهة ثابتة (HTML/CSS/JS) متصلة بقاعدة بيانات Supabase (مشروع `ghazl-factory`).
لا يوجد أي مفتاح سري في المستودع. المفتاح الموجود في `js/config.js` هو anon key العام.

## هيكل الملفات

```
index.html          نقطة الدخول وتحميل المكتبات بإصدارات ثابتة
css/style.css       التصميم: كحلي وذهبي، RTL، مناسب للموبايل أولاً
js/config.js        رابط Supabase ومفتاح anon العام فقط
js/app.js           الدخول والصلاحيات والشاشات الأساسية والتوجيه
js/features.js      شاشات إضافية: حضور متعدد الورديات، المكافآت والجزاءات،
                    حضور الإدارة، إدارة المديرين، تصدير Excel
README.md           هذا الملف
```

## الشاشات حسب الدور

| الشاشة | رئيس المجلس | مدير المصنع |
|---|---|---|
| الرئيسية (مؤشرات الحضور؛ الرواتب للرئيس فقط) | ✔ | ✔ (بلا أرقام مالية) |
| العمال (إضافة، تعديل، يومية، نقل، سجل اليوميات) | ✔ | إضافة وتعديل في مصنعه فقط |
| الحضور (حضور، انصراف، أكثر من وردية في اليوم) | ✔ | ✔ في مصنعه |
| الورديات | ✔ | ✔ في مصنعه |
| السلف | ✔ (إلغاء) | ✔ تسجيل وعرض |
| الرواتب (حساب، اعتماد، إغلاق، صرف، إعادة فتح) | ✔ | ✘ |
| المكافآت والجزاءات (تسجيل، اعتماد، رفض) | ✔ | ✘ |
| حضور الإدارة | ✔ | ✘ |
| المديرون (إنشاء، إيقاف، تفعيل، تغيير المصنع) | ✔ | ✘ |

## الطبقات الأمنية

1. **قاعدة البيانات:** RLS على كل جدول، وصلاحيات GRANT/REVOKE صريحة، ولا صلاحية DELETE على أي جدول.
2. **الجداول المالية** في schema مغلق `finance` لا يصل إليه أي دور مباشرة، والوصول عبر دوال تفحص `is_chairman()`.
3. **الكتابة عبر دوال RPC فقط**، تأخذ الهوية من `auth.uid()` ولا تقبل `recorded_by` من المتصفح.
4. **الحساب داخل قاعدة البيانات:** ساعات العمل والتأخير والإضافي والخصومات والرواتب، والمتصفح لا يحسب أي مبلغ.
5. **قفل الأسبوع:** أي تعديل على أسبوع غير مفتوح يحتاج رئيس المجلس وسبباً موثقاً، حتى عبر الاتصال المباشر.
6. **Edge Function `manage-managers`:** تتحقق أولاً أن المتصل رئيس المجلس، وتحتفظ بمفتاح service_role في أسرار Supabase فقط.

## التشغيل من الهاتف

1. ارفع الملفات إلى المستودع عبر **Add file ← Upload files** مع الحفاظ على المجلدين `css` و`js`.
2. فعّل GitHub Pages من **Settings ← Pages**: الفرع `main` والمجلد `/(root)`.
3. الرابط: `https://galalmo7amed77.github.io/erp-factories/`

## تسجيل الدخول

أدخل اسم المستخدم كما هو: `chairman` أو `fattaha_mgr` أو `textile_mgr` أو `spinning_mgr`.
كلمات المرور تُسلَّم منفصلة ولا تُكتب في أي ملف.

## ما هو مكتمل وما هو تحت الاختبار

راجع تقرير التنفيذ المرفق مع المحادثة للتفاصيل الكاملة للاختبارات وما لم يُختبر.

## قيود معروفة

- الاستعادة من النسخة الاحتياطية غير مُنفَّذة كزر، والتصدير فقط متاح.
- تصدير PDF يتم عبر "طباعة ← حفظ كـ PDF" في المتصفح، وليس بإنشاء ملف PDF برمجياً.
- الحضور يُسجَّل لكل وردية على حدة. الحضور اليومي المجمع لا يستبدل الحضور الفردي.
- لا يوجد حذف للعمال أو المديرين، والإيقاف يحفظ السجل التاريخي.
- تفعيل "حماية كلمات المرور المسرّبة" يتم من لوحة Supabase: Authentication ← Passwords.

## الخلفية (مجلد supabase)

```
supabase/migrations/   7 ملفات SQL بالترتيب (0001 إلى 0007): الجداول، الحماية، RLS، الدوال، الإعدادات
supabase/functions/    Edge Function: manage-managers (إنشاء وإدارة حسابات المديرين)
supabase/tests/        اختبارات الصلاحيات والوظائف + شرح تشغيلها
supabase/setup/        خطوات التشغيل من الصفر (بدون كلمات مرور)
```

تعليمات إعادة الإنشاء الكاملة موجودة في `supabase/setup/SETUP.md`.
